1. System Overview

The Requisition Portal is a Django-based enterprise web application that digitizes and streamlines internal resource requests — ICT equipment, transport, and office supplies — through a structured two-level approval workflow. It also integrates an HR module for contract generation, employee management, and payslip processing.

Key capabilities:

  • Three requisition types with independent approval chains
  • Role-based access control (requester, supervisor, department admin, full admin)
  • Email-driven approval workflow with signed action links
  • Public payslip request submission
  • HR contract generation with WeasyPrint PDF rendering
  • Full audit trail of all status changes
  • Self-service account registration with admin approval

3. System Modules

3.1 ICT Requisition

Handles requests for IT equipment, software licenses, and accessories. Features include supervisor selection, multi-item equipment lists, and specification details.

Models: ICTRequisition

3.2 Transport Requisition

Manages vehicle transport requests for official trips. Supports vehicle type selection, pick-up/drop-off scheduling, passenger count, driver assignment, and Excel report export.

Models: TransportRequisition, Driver

3.3 Internal Requisition

Covers office supplies, stationery, and internal resources. Supports multi-item requests with quantities and purposes per item.

Models: InternalRequisition, InternalEquipmentItem

3.4 Accounts & Authentication

Custom user model with role-based permissions. Supports self-registration (admin must approve), user management, and role assignment.

Models: User (extends AbstractUser)

3.5 Contracts (HR)

Full contract lifecycle: create, bulk upload, email delivery, PDF generation. Includes email configuration per department, bulk email status tracking, and a system manual.

3.6 Employees (HR)

Employee database with CRUD operations, salary tracking, and CSV import.

Models: Employee, EmployeeSalary

3.7 Payslip (HR)

Payslip creation, PDF generation, bulk upload, and a public request form where non-logged-in users can submit payslip requests by name, PIN, and month selection.

Models: Payslip, PayslipRequest

3.8 Notifications

Per-department email configuration, email logging with retry capability, signed action tokens for one-click approve/reject from email, and requisition tracking page.

Models: EmailConfig, EmailLog, AuditLog

5. Requisition Workflow

Standard Two-Level Approval

  1. Submit — Requester fills and submits the form (authentication required)
  2. First Approval — Supervisor (or department admin) receives an email with Approve/Reject links. Approving moves status to Pending Second Approval.
  3. Second Approval — ICT Approver (or admin) receives notification. Approving marks the requisition as Approved.
  4. Rejection — At any step, the approver can reject with a reason. The requester receives a notification email.

Email links use signed tokens (7-day expiry) for one-click action without logging in.

ICT-Specific Flow

ICT requisitions allow selecting a specific supervisor as the first approver. If selected, the approval request goes directly to that supervisor instead of broadcasting to all supervisors.

Transport-Specific Flow

After approval, an admin or transport admin can assign a driver (name, car number, cell). The requester receives a notification with driver details.

6. HR Module

The HR module is accessible at /hr/contracts/, /hr/employees/, and /hr/payslip/. It uses its own base template with a dedicated sidebar.

Contracts

  • Create individual contracts with full employee details, salary, and terms
  • Bulk upload contracts from CSV
  • Generate and download contract PDFs
  • Send contracts via email with CC functionality
  • Bulk email with status tracking per recipient
  • Per-department email configuration (SMTP settings)

Employees

  • Employee directory with search and detail view
  • Salary records per employee
  • CSV import for bulk employee data
  • API endpoint: /hr/employees/api/<pin>/ (used by contract form for auto-fill)

Payslip

  • Create individual payslips with earnings and deductions
  • Bulk upload payslip data
  • PDF generation for each payslip
  • Payslip Request — Public form at /hr/payslip/request/ where anyone can submit a payslip request by name, PIN, and selected months. HR admin reviews and processes these at /hr/payslip/requests/.

7. Notifications

Email Configuration

Each department (ICT, Transport, Internal) can have its own SMTP configuration stored in the database. Admins can enable/disable per-department email.

Email Logs

All sent emails are logged with status (sent/failed). Failed emails can be retried individually or in bulk. The log shows department, email type, recipient, subject, and any error messages.

Action Tokens

Approval and rejection links in emails contain cryptographically signed tokens with the requisition ID, action, and approver ID. Tokens expire after 7 days.

Tracking Page

Each requisition has a public tracking page (linked from notification emails) showing current status without requiring login.

8. Audit Log

All status changes on requisitions are recorded in the AuditLog model:

  • Created — When a requisition is submitted
  • Pending Second Approval — After first-level approval
  • Approved — After second-level approval (fully approved)
  • Rejected — When rejected at any stage (includes rejection reason)

Each entry records: requisition type, request number, action, user who performed it, timestamp, and optional details. Admins can view all logs at /notifications/audit-log/; regular users see only actions on their own requisitions.

9. Deployment

Production Setup

  • Web Server: nginx on port 80, reverse proxy to gunicorn
  • Gunicorn: 3 workers on 127.0.0.1:8001
  • Service: systemd unit requisition_portal.service, auto-restarts on failure and boot
  • Static Files: served directly by nginx from STATIC_ROOT

Required System Libraries

  • Python 3.x + pip
  • libpango, libcairo, libgdk-pixbuf2.0-dev (for WeasyPrint PDF generation)

Environment Variables

Key settings in settings.py:

  • AUTH_USER_MODEL = 'accounts.User'
  • LOGIN_URL = '/accounts/login/'
  • LOGIN_REDIRECT_URL = 'dashboard'
  • Q_CLUSTER configured for django-q2 async tasks
